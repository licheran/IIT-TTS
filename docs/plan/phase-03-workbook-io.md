# Phase 3 — Workbook import/export

**Goal:** the lossless Excel/CSV contract.

## Read first
- `docs/spec/03-workbook-format.md` (all)
- `docs/spec/02-domain-model.md` §6

## Tasks
- [x] P3.1 `presets/academic_weekly/sheets.py`: sheet definitions (name, columns, required, type, reference target, core mapping, label) for every sheet in spec 03 §2. `io` reads only these definitions, with no sheet-specific code paths except the join-sheet expansion helpers.
- [x] P3.2 `io/workbook.py` export: sheet order, frozen header, data-validation dropdowns for reference columns, `_meta` with `format_version=1`, and an `Assignments` sheet when a `Result` is given.
- [x] P3.3 Import:
  - Parse the sheets, and treat `x_` columns as notes.
  - Coerce types, and expand convenience lists into join rows.
  - Resolve references and check the invariants.
  - Collect **all** errors (spec 03 §3 format), and build the `Dataset` only if there are none.
- [ ] P3.4 `io/csvzip.py`: the same contract for a CSV zip.
- [ ] P3.5 Round-trip tests on L6 and on hypothesis-generated datasets: `import(export(ds)) == ds`, and `x_` columns survive.
- [ ] P3.6 An error-collection test: a workbook with 5 seeded errors of different kinds reports all 5 with the correct sheet, row, column and message.
- [ ] P3.7 Save `tests/fixtures/l6/l6.xlsx` (generated by `import-fet`). CLI `export` works.
- [ ] P3.8 A performance test (`scale` marker): a 10,000-row workbook imports in ≤ 10 s (NFR-4).

## Acceptance
- The round-trip and error-collection tests pass.
- `l6.xlsx` opens in Excel or LibreOffice with working dropdowns (check by hand, and note it in STATUS).

## Out of scope
The database and UI.
